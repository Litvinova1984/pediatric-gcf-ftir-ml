# Pediatric GCF ATR-FTIR — carrier correction and clinical spectral contrasts

**Version:** v1.0.0 reproducibility package (release candidate, 25 November 2026)  
**Manuscript:** *Интеллектуальный анализ инфракрасных спектров десневой жидкости детей, сорбированной на бумажном носителе: выделение клинически ассоциированных признаков*.  
**Funding:** Russian Science Foundation, project 26-15-00389.

## Scientific scope

This research examines gingival crevicular fluid (GCF) ATR-FTIR measurements on absorbent paper strips. It differs from the authors' earlier *Applied Sciences* and *Data* analyses of some of the same pediatric spectra by investigating whether C–H and amide spectral variation is associated with clinically documented periodontal status after explicit paper-carrier adjustment.

The R workflow comprises technical strip control, extended multiplicative signal correction (EMSC) using the mean of four clean paper strips (DPT4), unsupervised PCA in the 1540–1720 and 2870–3050 cm⁻¹ windows, exploratory exact permutation tests and Cliff's delta, age-restricted and carrier-sensitivity comparisons, passive projection of four physician-designated reference samples, and nonnegative matrix factorization (NMF) with a fixed carrier and a constant component. Clinical labels are not used in fitting PCA.

**Interpretation:** these are exploratory clinical associations, not a diagnostic classifier or chemical identification. The main comparison has three children with documented periodontal pathology and 22 without a documented periodontal pathology label. The 22 are not a verified healthy cohort; the four external samples are not an independent diagnostic validation cohort.

## Reproduce the analysis

Install R; no third-party R packages are required. From the repository root:

```bash
Rscript run_all.R
Rscript verify_local_results.R
```

Alternatively, in RStudio use `source(file.choose(), encoding = "UTF-8")` and select `run_all.R`, then `verify_local_results.R`. Outputs are generated into `R/results/`, which is excluded from Git and is **not distributed** in this package because it contains individual PCA scores and other participant-linked analytical objects. The approved publication outputs and figures are in `outputs/` and `figures/`.

On macOS without XQuartz, the scripts skip optional Cairo PDFs and still generate the publication PNGs. Figure curves, labels, highlight bands and spectroscopic annotations come from the R scripts; figures are not edited manually.

**Validated state:** the author ran the prepared-input analytical pipeline on Mac mini (R 4.6.2, macOS Tahoe), generated both final PNGs into the correct `R/results/`, and reported `PASS: 5/5 numeric checks, NMF summary present, 2 final PNG present`. The path-corrected graphics were rerun after the initial path issue; the root one-command `Rscript run_all.R` was not separately tested in a newly unpacked copy. The repository files preserve the verified code and frozen aggregate outputs. See `docs/VERIFICATION.md`.

## Reproducibility boundary and data availability

This release starts from the **prepared absorbance** master matrix, not raw instrument files. The previous article in *Data* released a different, SNV-normalized pediatric matrix; that input cannot replace the absorbance matrix required for carrier adjustment here. Original `.spc`/`.dpt` acquisition and conversion to this prepared matrix are outside the reproducible scope.

The shared input uses pseudonyms and does not include exact ages, sex, endocrine/UCTD metadata, medical chart numbers or source filenames. It **does** contain per-spectrum periodontal-status and 14–17-year age-band indicators required for the clinical tests. Pseudonymization does not prevent linkage to previously released spectra. **Before making the GitHub repository public, the research team must confirm that consent, ethics approval and applicable data-governance requirements permit this new pairing of individual spectra with clinical flags.** If permission is unavailable, omit the linked input and describe controlled-access reproduction instead. See `docs/DATA_AVAILABILITY.md`.
